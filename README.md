# Менеджер рассылок.

Веб-приложение на Django, которое позволяет пользователям управлять рассылками сообщений 
для клиентов. Приложение включает функциональность для создания, просмотра, 
редактирования и удаления рассылок, а также отправки сообщений по требованию.

# Инструкция по установке и использованию разработанного функционала приложения
1. Клонируйте репозиторий:
```
git clone https://github.com/4usnok/Project_4_Mailing_manager.git
```
2. Установите зависимости:
```
pip install -r requirements.txt
```
# Содержание проекта
## Приложение `client` 
Функционал работы с клиентами(получателями рассылок):
1. Приложение позволяет создавать, удалять, редактировать и просматривать карточки со всей информацией о клиентах;
2. В директории `templates/client` находится директория `crud`. В ней реализованы шаблоны 
* для удаления -> `client_delete.html`
* для просмотра -> `client_detail.html`
* для формы -> `form_client`
3. За пределами директории `templates/client/crud` находится шаблон `client_list_page.html` для просмотра списка всех карточек 
с данными о клиентах;
4. Остальной функционал CRUD находится в `views.py`:
* Класс `ClientAddView`: для добавления клиента
* Класс `ClientDeleteView`: для удаления клиента
* Класс `ClientUpdateView`: для редактирования клиента
* Класс `ClientDetailView`: для просмотра подробной информации
* Класс `ClientFormView`: для формы клиента
5. В `urls.py`, соответственно, находятся маршруты, которые активно используются в шаблонах
6. В `models.py` описаны модели
* Модель получателя рассылки -> `Recipient`

## Приложение `users`: 
Функционал работы с пользователями
1. Основной функционал приложения, позволяет работать пользователями(регистрация и аутентификация) 
2. В директории `templates/users` находится директория `registration`. В ней реализованы шаблоны:
* об оповещении ошибки активации -> `email_confirmation_failed.html`
* об оповещении высланном письме для активации аккаунта -> `email_confirmation_sent.html`
* об оповещении успешной активации аккаунта -> `email_confirmed.html`
* об оповещении успешной смены пароля от аккаунта -> `password_reset_complete.html`
* для формы сброса пароля -> `password_reset_confirm.html`
* об оповещении высланном письме для сброса пароля -> `password_reset_done.html`
* для заполнения содержимого письма на почту -> `password_reset_email.html`
* для формы email, который привязан к аккаунту -> `password_reset_form.html`
3. формы клиента. За пределами директории `templates/users/registration` находится шаблоны
* для входа на аккаунт -> `login_user.html`
* для выхода с аккаунта -> `logout_user.html`
* для регистрации аккаунта -> `register.html`
* для списка с пользователями -> `users_list`
с данными о клиентах;
4. Остальной функционал CRUD находится в `views.py`:
* Класс `UserListView` -> для просмотра списка пользователей
* Класс `UserRegisterView` -> для регистрации
* Класс `UserConfirmEmailView` -> для обработки запроса на активацию аккаунта
* Класс `EmailConfirmationSentView` -> для успешного запроса на подтверждение аккаунта
* Класс `EmailConfirmedView` -> для окончания подтверждения аккаунта
* Класс `UserBlock` -> для блокировки юзера
5. В `urls.py`, соответственно, находятся маршруты, которые активно используются в шаблонах
6. В `models.py` описаны модели
* Модель для пользователей -> `UsersList`

# Принцип работы с приложением
* Принцип работы заключается в посылании GET-запроса и принятии POST-запроса,
* В первую очередь необходимо заполнить пространство имён в текстовом файле `.env.sample`. 
* СУБД, которая используется в приложении -> postgresql
* `python manage.py runserver` -> запускает приложение
* После чего, в консоли появляется вся необходимая информация: статус-код, ссылка для перехода и тд.,
* Перейдя по ссылке из консоли с описанном в `.env.sample`, Django осведомит о 404 ошибке (Page not found 404) после чего, предложит добавить в адресную строку представленные namespace,

# Полезные команды
* Запуск сервера: `python manage.py runserver`,
* Создание суперюзера(админка): `python manage.py createsuperuser`,
* Создание миграций: `python manage.py makemigrations`,
* Сохранение миграций: `python manage.py migrate`,
* Откат всех миграций: `python manage.py migrate name_migration`, где `name_migration` -> название миграции.
